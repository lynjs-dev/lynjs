# 모노레포에서 LynJS와 Babel Preset 버전을 동일하게 관리하기

모노레포를 운영하다 보면, 여러 패키지가 각각 독립적인 버전을 가지게 되면서 예상치 못한 불일치가 발생하는 경우가 많다.
예를 들어, `lynjs`의 버전은 `0.1.0-next.2`로 올라갔지만, `babel-preset-lynjs`는 여전히 `0.1.0-next.1`에 머물러 있는
상황이 생길 수 있다. 이런 불일치는 단순히 숫자가 다른 문제로 끝나지 않는다.

프리셋과 런타임은 기능적으로 긴밀히 연결되어 있기 때문에, 버전이 어긋나면 실제 코드에서는 정상 동작하더라도 빌드나
테스트, 혹은 CI/CD 과정에서 호환성 문제가 발생할 수 있다. 예를 들어, `babel-preset-lynjs`가 이전 버전의 변환 규칙을
유지하고 있다면, 최신 `lynjs` 코드가 의도한 방식으로 트랜스파일되지 않아 런타임 오류로 이어질 가능성이 있다.

이런 문제를 근본적으로 해결하기 위해서는 **프리셋과 런타임의 버전을 항상 함께 관리하는 일관된 체계**가 필요하다. 특히
배포와 테스트, 그리고 CI 자동화가 포함된 환경에서는 버전 동기화가 필수적이다. LynJS 프로젝트에서는 이러한 문제를
최소화하기 위해 **모든 핵심 패키지가 동일한 버전으로 움직이는 버전 관리 전략**을 채택하려고 한다.

## 같은 프로젝트인데 버전이 다르다?

모노레포는 여러 패키지를 하나의 저장소에서 함께 관리할 수 있어 효율적이지만, 각 패키지가 **별도의 `package.json`과 버전
필드**를 가지고 있다는 점에서 관리 복잡도가 높다. 특히 릴리스를 자주 하는 프로젝트일수록, 한두 패키지의 버전이 뒤처지는
상황이 자주 발생한다.

예를 들어 LynJS처럼 `lynjs`와 `babel-preset-lynjs`가 함께 동작해야 하는 환경에서, `lynjs`만 `npm version patch`를
수행하고 프리셋은 그대로 두면 버전이 어긋난다. 결과적으로 `npm publish` 시 한쪽만 새 버전으로 배포되거나, 패키지 간
의존성 범위가 달라 `peerDependencies` 충돌이 발생할 수도 있다.

더 문제는, 이런 불일치가 **눈에 잘 띄지 않는다는 점**이다. 문서상 버전은 최신으로 표시되어 있고, CI 로그에서도 문제가
없어 보이지만 실제 설치된 `node_modules`에는 구버전 프리셋이 남아 있는 식이다. 이런 “보이지 않는 버전 차이”는 빌드
오류보다도 더 골치 아픈 문제를 만든다.

물론 수동으로 맞추는 방법도 있다. `package.json`을 수정하고, 커밋 후 `npm version`, `git push`, `git tag`를 반복하는
식이다. 하지만 프로젝트가 커질수록 이 과정은 점점 더 비효율적으로 변하고, 결국 **자동으로 버전을 맞추는 체계적인
방식**이 필요해진다.

## 버전 동기화 전략 세우기

모노레포에서 여러 패키지를 함께 관리할 때는 두 가지 대표적인 버전 관리 방식이 있다.

### 개별 관리 (Independent mode)

- 각 패키지가 **자신만의 버전**을 가진다.
- `lynjs`는 `0.1.5`, `babel-preset-lynjs`는 `0.3.2`처럼 버전을 독립적으로 올릴 수 있다.
- 장점: 변경이 적은 패키지는 그대로 두고, 수정된 패키지만 배포 가능.
- 단점: 릴리스 주기가 어긋나면 서로 호환되는 버전을 맞추기 어려워짐.

### 일괄 관리 (Fixed mode)

- **모든 패키지가 항상 동일한 버전으로 이동**한다.
- `lynjs`, `babel-preset-lynjs` 모두 `0.1.0 → 0.1.1`로 함께 업데이트.
- 장점: 버전 일관성 확보, 태그·배포 관리 단순화, CI/CD 동기화 용이.
- 단점: 한 패키지의 사소한 변경에도 전체 버전이 올라감.

`lynjs`와 `babel-preset-lynjs`는 JSX 변환 규칙이 변경되면 런타임 동작도 반드시 맞춰야 하고, 둘의 기능 릴리스 주기가
완전히 동일한 **강하게 연결된 한 세트**이기 때문에 LynJS는 **일괄 관리(Fixed mode)** 전략을 채택했다.

버전을 함께 관리하면 릴리스 태그(`v0.1.0-next.2`)도 하나로 통일되며, GitHub Actions나 npm 배포 자동화 시에도 **한 번의
태그로 모든 패키지를 배포**할 수 있어, LynJS가 추구하는 “코드·문서·빌드의 일관성”은 버전 관리에서도 그대로 이어진다.

## 버전 동기화 구현

LynJS 모노레포에서는 **루트 패키지(`lynjs`)가 단일 버전의 기준점**이며, 릴리스 버전을 결정하는 주체는 루트 패키지다.
루트 패키지와 버전을 동기화해야 하는 모든 서브 패키지(`babel-preset-lynjs` 등)는 루트 패키지의 버전을 그대로 따라야
한다.

루트에서는 **semantic-release**를 사용하고 있으며, semantic-release는 커밋 메시지를 자동으로 분석해 다음 버전을
산출하고, 태그 생성과 changelog 작성, npm 배포까지 전 과정을 자동화해준다. 하지만 기본 설정만으로는 루트 패키지만
갱신되고, 내부 패키지의 버전은 그대로 남는다는 한계가 있다.

서브 패키지가 루트 패키지의 버전을 따르도록 하기 위해 **버전 동기화 스크립트(`scripts/sync-preset-version.js`)**를
추가해야 한다. 이 스크립트는 semantic-release가 새 버전을 계산할 때마다 `nextRelease.version` 값을 전달받아,
`packages/babel-preset-lynjs/package.json`의 `version` 필드와 `lynjs` 관련 의존성을 자동으로 동일하게 업데이트한다.

이후 semantic-release의 `@semantic-release/npm` 플러그인이 루트 패키지와 `babel-preset-lynjs`를 **같은 버전으로 동시에
publish**하도록 설정해야 한다.

결과적으로 한 번의 semantic-release 실행으로

- 루트(`lynjs`)와 프리셋(`babel-preset-lynjs`)의 버전이 항상 일치하고,
- 동일한 태그(`v0.x.x` 또는 `v0.x.x-next.y`)가 자동으로 생성되며,
- changelog, Git 커밋, GitHub 릴리스, npm 배포까지 완전히 동기화된 릴리스가 만들어진다.

이렇게 구성하면 **“하나의 릴리스 = 하나의 버전 = 하나의 태그”**라는 LynJS의 버전 관리 원칙을 자동으로 보장할 수 있다.

### 버전 동기화 스크립트 작성

이 스크립트는 **semantic-release가 새 버전을 계산할 때마다 자동으로 실행**되어, 루트 패키지(`lynjs`)와
`packages/babel-preset-lynjs`의 버전을 항상 일치시키는 역할을 한다.

`semantic-release`는 `nextRelease.version` 값을 제공하는데, 이 값을 명령행 인자로 받아 `babel-preset-lynjs`의
`package.json` 파일에 직접 주입하는 방식이다. 이를 통해 루트 패키지에서 릴리스가 진행될 때, 프리셋 패키지도 **같은 버전
번호로 자동 갱신**된다.

**주요 동작 :**

1. **버전 인자(nextVersion) 확인**: semantic-release가 전달한 버전 번호를 세 번째 인자로 받아 사용함 (예:
   semantic-release가 `0.1.2-next.4`를 계산했다면, `node scripts/sync-preset-version.js 0.1.2-next.4` 형태로 실행)

2. **프리셋 package.json 로드 및 갱신**: `packages/babel-preset-lynjs/package.json` 파일을 읽어 `version` 필드를 새로운
   버전으로 교체

3. **의존성(lynjs) 버전 동기화**: 프리셋이 `lynjs`를 직접 참조하는 경우(`dependencies`나 `peerDependencies`에 존재할
   때), 프리셋이 항상 **현재 루트 버전의 런타임을 대상으로 빌드**되도록 보장할 수 있도록 참조 버전도 동일하게 업데이트

4. **결과 저장 및 로그 출력**: 수정된 JSON을 다시 파일로 저장하고, 콘솔에
   `[sync] packages/babel-preset-lynjs -> 0.1.2-next.4`처럼 실행 결과를 출력

**실행 타이밍 :**

이 스크립트는 semantic-release 설정(`.releaserc.cjs`)에 다음처럼 등록록하여 **prepare 단계**에서 루트 패키지의 다음
버전이 계산된 직후 프리셋의 `package.json`이 새 버전으로 갱신되도록 한다.

```js
[
  '@semantic-release/exec',
  {
    prepareCmd: 'node scripts/sync-preset-version.js ${nextRelease.version}',
  },
];
```

**scripts/sync-preset-version.js**

```js
import fs from 'node:fs';
import path from 'node:path';

const [, , nextVersion] = process.argv;
if (!nextVersion) {
  console.error('nextVersion is required, e.g. 0.1.0');
  process.exit(1);
}

const presetPath = path.resolve('packages/babel-preset-lynjs/package.json');
const presetJson = JSON.parse(fs.readFileSync(presetPath, 'utf8'));

presetJson.version = nextVersion;

// Synchronize lynjs dependencies/peer dependencies as well (only when present)
if (presetJson.dependencies?.lynjs) {
  presetJson.dependencies.lynjs = nextVersion;
}
if (presetJson.peerDependencies?.lynjs) {
  presetJson.peerDependencies.lynjs = `^${nextVersion}`;
}

fs.writeFileSync(presetPath, JSON.stringify(presetJson, null, 2) + '\n');
console.log(`[sync] packages/babel-preset-lynjs -> ${nextVersion}`);
```

### semantic-release 설정

위에서 작성한 **버전 동기화 스크립트(`scripts/sync-preset-version.js`)**를 실행하기 위해, 이전에 구성한 semantic-release
설정을 다음과 같이 수정한다.

1. **버전 동기화 스크립트 실행 추가**

   ```js
   [
     '@semantic-release/exec',
     {
       // Inject nextRelease.version into preset package.json
       prepareCmd: 'node scripts/sync-preset-version.mjs ${nextRelease.version}',
     },
   ];
   ```

   semantic-release가 새 버전을 계산하면 `prepare` 단계에서 위 명령이 실행된다. 이를 통해 루트
   버전(`${nextRelease.version}`)이 `packages/babel-preset-lynjs/package.json`에 자동 반영되어, 루트 릴리스와 프리셋
   릴리스가 항상 동일한 버전으로 동기화된다.

2. **프리셋 패키지 동시 배포 설정 추가**

   ```js
   isCI && ['@semantic-release/npm', { pkgRoot: 'packages/babel-preset-lynjs', tarballDir: 'dist-tarball' }],
   ```

   semantic-release는 기본적으로 루트 패키지만 npm에 배포한다. 위 설정을 추가하면, 동일한 릴리스 과정에서
   `packages/babel-preset-lynjs` 디렉터리도 **별도의 npm 패키지로 함께 publish**된다. 이렇게 하면 루트(`lynjs`)와
   프리셋(`babel-preset-lynjs`)이 항상 같은 버전으로 동시에 배포된다.

3. **Git 커밋 대상에 프리셋 패키지 추가**
   ```js
   assets: ['CHANGELOG.md', 'package.json', 'packages/babel-preset-lynjs/package.json'];
   ```
   릴리스 과정에서 변경된 프리셋의 `package.json` 파일이 Git 커밋에 포함되도록 수정하여, 동기화된 버전 정보가 릴리스
   커밋에 함께 기록되도록 한다.

**.releaserc.cjs**

```js
const isCI = !!process.env.CI; // Default is true in GitHub Actions

module.exports = {
  repositoryUrl: 'git@github.com:lynjs-dev/lynjs.git',
  branches: ['main', { name: 'next', prerelease: true }],
  plugins: [
    [
      '@semantic-release/commit-analyzer',
      {
        preset: 'conventionalcommits',
        releaseRules: [
          { breaking: true, release: 'major' },
          { type: 'feat', release: 'minor' },
          { type: 'fix', release: 'patch' },
          { type: 'docs', release: false },
          { type: 'docs', scope: 'release', release: 'patch' },
          { type: 'chore', release: false },
          { type: 'chore', scope: 'release', release: 'patch' },
        ],
      },
    ],
    ['@semantic-release/release-notes-generator', { preset: 'conventionalcommits' }],

    [
      '@semantic-release/exec',
      {
        // Inject nextRelease.version into preset package.json
        prepareCmd: 'node scripts/sync-preset-version.mjs ${nextRelease.version}',
      },
    ],

    // === The following 4 plugins only run in CI ===
    isCI && ['@semantic-release/changelog', { changelogFile: 'CHANGELOG.md' }],
    isCI && ['@semantic-release/npm', { tarballDir: 'dist-tarball' }],
    isCI && ['@semantic-release/npm', { pkgRoot: 'packages/babel-preset-lynjs', tarballDir: 'dist-tarball' }],
    isCI && ['@semantic-release/github', { assets: 'dist-tarball/*.tgz' }],
    isCI && [
      '@semantic-release/git',
      {
        assets: ['CHANGELOG.md', 'package.json', 'packages/babel-preset-lynjs/package.json'],
        message: 'chore(release): ${nextRelease.version} [skip ci]\n\n${nextRelease.notes}',
      },
    ],
  ].filter(Boolean),
};
```
